# 本机Codex制作执行器

中台在Docker中运行；此执行器在装有Codex的宿主运行，复用已登录的Codex账号。只处理一个已指定品牌的六类商品制作任务，不提供任意命令或任意文件入口。所有调用使用该品牌已有MCP令牌的权限。

启动前核`codex login status`，将品牌令牌设置到本机进程环境，不写源码或配置Git；在Lab源码根执行：

```powershell
node integrations/commerce/executor/worker.cjs --brand <品牌ID> --token-env OMNI_BRAND_TOKEN --codex-path <已安装codex.exe的绝对路径>
```

默认MCP为本机23011；其他部署显式提供`--endpoint`。凭据通过已有环境变量传入，不放命令参数、不回显。新机安装技能后仍需登录Codex、连接本品牌和启动此执行器；技能文件本身不是常驻执行服务。不自动添加计划任务、自启或修改全局Codex配置。

在线后页面显示可用按钮。选择商品→创建项目或打开既有项目→生成文案/方案→检查当前内容→按范围生成画面。商品视频先确认当前创意、应用、分辨率、比例、时长。生成与商家上架独立。图片/视频适配器按实时目录可用性启用，付费服务需已有有效配置。

状态保存在被Git忽略的`.local/commerce-executor/<brand>/`：events.jsonl、每任务的请求上下文、Codex结果、调用意图及实际供应商回执。这里含品牌资料，按私有运行数据管理；不要加入公开技能仓或发给第三方。Codex子进程不继承品牌令牌/API密钥，模型只接收已选商品和本任务所需领域方法。

任务串行；同项目并行请求被服务端拒绝。CLI网络自动回退或重连可能增加首次耗时，页面保留原任务；不要重复点生成。退出/断网后租约过期会要求核对原版本和供应商任务，收费结果不明不能盲目重提。停止当前进程即可，心跳90秒后离线。启动命令窗口可用Ctrl+C；后台部署应保存自身PID并只停止该执行器进程。

本轮已验证文本任务真实调用与新版本回写；媒体字段适配及受控原图读取单独验证，付费生成与最终画面/声画审核必须以实际任务回执和人工预览确认。

## 402 电商执行与修订

402修订：现有六任务支持generationMode=revise，指定revisionScope及targetIndexes。文字只改所选范围；图片以当前受控原图编辑，原图读取受品牌/项目/CAS限制；视频先改创意，再确认当前参数并重新生成，不支持任意逐帧视频修补。具体实现与验收见../../../docs/changes/2026-10-27-commerce-operator-revision.md。

## 403 经营重规划

新增第七种能力operations_replan；沿当前品牌队列处理经营计划，不依赖商品制作项目。冻结计划、目标与版本，Codex生成七类策略/完整指标/三档费用；逐层校验后CAS保存，失败保留原方案。每档各动作现金加总必须对账。分类group与六个数据stage分开，反向指标行动关联也校验。网络重连可能增加耗时，勿重复派发；子进程超20分钟失败并保留草稿。没有新增自动采集、自启或店铺写功能。

规划失败可恢复同输入/同源版本的私有Codex草稿，先校验再保存，原失败记录保留；新目标或反馈不得复用。已存在指标ID锁定原始数据身份和公式，三个目标同时核验。重启执行器前先确认无活动任务并等旧90秒心跳过期，服务端不允许并发接管。
