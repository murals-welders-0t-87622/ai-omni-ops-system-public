# 素材业务数据查询减负

业务素材的采集原始回执可能很大，原查询反复从同一 JSON 中提取多个字段，会增加数据库解压和读取开销。现以品牌与原有类型条件筛选后，使用 PostgreSQL 物化查询，一次整理每条记录的元数据，再读取各字段。原始回执仍保留在数据库；素材筛选、跨来源排序、总数和品牌边界保持原有规则。

独立环境已有数据的四个品牌上，旧版和候选版的业务素材结果一致；每个品牌的首页、翻页、视频筛选及原片 ID 检索完整响应均一致。最大样本的业务素材查询对照约 0.87 秒降至 0.41 秒；这是单机样本，不代表所有数据量或整机性能。真实数据库只读合成数据覆盖品牌隔离、类型排除、对象/数组/标量/空 JSON 及原始回执保留。未改变数据或 schema。

构建后可在独立测试 PostgreSQL 设置 `DATABASE_URL`，执行 `node scripts/test-material-business-query.cjs`；此测试仅在 SQL 中使用临时 VALUES，不写入表。`node scripts/test-material-archive.cjs` 验证素材档案现有规则。数据仍全量读取，全局分页方案及低配长期压力测试尚未完成。
