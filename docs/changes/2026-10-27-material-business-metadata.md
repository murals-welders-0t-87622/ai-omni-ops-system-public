# 业务素材元数据读取减负

在素材档案查询中，正文已经作为 `textContent` 单独返回，一些经营报表、原始结果和展示字段既不参与档案关联，也不参与作品快照。查询响应中的内部元数据不再重复携带这些字段；数据库中的完整记录不变，正文关键词仍可检索。

只读对照四个品牌的素材记录内容及 24 组完整档案响应一致，包含分页、视频、原片和产品过滤。一个品牌的 310 条业务素材元数据 JSON 序列化约 1.58 MB 降到 0.10 MB；这不是数据库网络流量或整机内存测量。原始 SQL 对相同创建时间的内部行顺序可能不同，档案接口本身仍按时间和记录标识排序。

服务端构建、素材回归、14 种作品类型快照对照和隔离测试通过；设置独立 PostgreSQL 的 `DATABASE_URL` 后执行 `node scripts/test-material-business-query.cjs`，使用合成数据只读验证文本检索、品牌隔离及 JSON 边界。若今后作品快照需要读取目前省略的字段，必须同步调整查询投影及快照回归。素材仍全量读取，低配置与长期运行需进一步验证。
